# ShopFlow AI — Demo Runbook

Everything needed to run the live demo reliably, with the exact outputs to
expect at each step.

**Live URL:** https://d3m3lwn03zb2eu.cloudfront.net (no login)

> **All demo data is synthetic.** 147 SKUs generated by `data/generator.py` at a
> fixed seed, modelled on a Madurai electrical retailer. Say this out loud
> during the demo — it costs nothing and protects every other claim you make.

---

## STEP 0 — RESET DEMO STATE *(do this first, every time)*

**This is not optional.** Confirmed supplier costs are durable and shop-wide by
design. If a previous rehearsal confirmed the ₹6,300 wire price, the demo starts
mid-story: the "before" state is gone, and the price list no longer shows a
+6.78% change against it.

```bash
python scripts/reset_confirmed_costs.py            # dry run — lists what exists
python scripts/reset_confirmed_costs.py --confirm  # actually clears
```

Expected when already clean:

```
No confirmed supplier costs for SHOP#demo. Already at seeded state.
```

Expected when a rehearsal left state behind:

```
1 confirmed supplier cost(s) under SHOP#demo:

  W-FIN-1.5-RED-90M        Rs 6300 INR  from job a250d927...

Deleted 1 record(s). The shop is back to seeded costs.
```

### Verify the reset took effect

```bash
curl -s -X POST https://d3m3lwn03zb2eu.cloudfront.net/api/purchase-plans \
  -H "content-type: application/json" -d '{"budget":25000}'
```

Three things must be true before you demo:

| Check | Required value |
|---|---|
| Wire supplier cost | **₹5,900.00** |
| `costSource` | **`SEEDED_SUPPLIER_PRICE`** |
| `confirmedCosts` count | **0** |

PowerShell one-liner:

```powershell
$p = (Invoke-WebRequest "https://d3m3lwn03zb2eu.cloudfront.net/api/purchase-plans" `
  -Method POST -Body '{"budget":25000}' -ContentType "application/json" `
  -UseBasicParsing).Content | ConvertFrom-Json
$w = $p.commitments | Where-Object { $_.skuId -eq "W-FIN-1.5-RED-90M" }
"cost=Rs $($w.unitCost)  source=$($w.costSource)  confirmed=$($p.confirmedCosts.Count)"
```

Expected: `cost=Rs 5900.0  source=SEEDED_SUPPLIER_PRICE  confirmed=0`

### The reset script is not, and must not become, a public endpoint

There is **no API route and no UI button** for reset, deliberately. Erasing what
a shop owner agreed to pay is not something a web request should be able to do.
It runs only from a machine with AWS credentials, lists by default, and deletes
only with an explicit `--confirm`. **Do not add a route for it to make demoing
easier.**

## R. What happens when it breaks *(60 seconds — for a technical audience)*

Run this after Step A, while the finished quotation is still on screen. It is
an architecture moment, not a feature moment, and it is the one a judge with an
operations background will care about most.

**R1 — name the defect first.** Open the AWS console at SQS and show the two
queues: `shopflow-orders` and `shopflow-orders-dlq`.

**Say:** *"During our own architecture review we found a real defect. The API
used to hand each order to the worker with an asynchronous Lambda invoke, with
retries turned off. If that invoke failed, nothing retried it and nothing
recorded it — the order sat at QUEUED until its TTL removed it, and the browser
polled something that was never going to finish. An order could be lost
silently."*

**R2 — show the fix.** Open `shopflow-orders` → **Dead-letter queue** and show
the redrive policy: maxReceiveCount **3**, target `shopflow-orders-dlq`.

**Say:** *"Now it goes on a durable queue. Three attempts, then a dead-letter
queue we can actually open, and an alarm on it. We did not add SQS to use SQS —
we added it because we found the order could disappear."*

**R3 — the account constraint.** Open Lambda → `shopflow-order-worker` →
**Configuration → Triggers**, and show the SQS trigger's maximum concurrency of
**5**.

**Say:** *"This account has a total Lambda concurrency of ten, shared with
every other project in it. Left unbounded, a burst of queued orders would scale
this worker until the API had none left and the public site started failing.
Five leaves five."*

**R4 — the DLQ should be empty.** Show `shopflow-orders-dlq` with zero messages
available.

**Say:** *"Empty is the expected state, and the alarm fires on a single
message — because the right number of dead-lettered customer orders is zero."*

> **Do not claim** automatic recovery. A message that reaches the dead-letter
> queue leaves the job at PROCESSING, and **nothing repairs it automatically**.
> The honest claim is: *the failure is now durable, bounded, visible and
> attributable to a jobId* — which is four things it was not before.
>
> **Do not claim** the alarms notify anyone. There is no SNS topic in this
> stack yet. They change state in the console. Say that.

## I. "Why?" — the evidence

Expand **Why?** on any deferred restock. Example (`SW-ANC-BELL`):

```
reason:  Deferred: remaining budget cannot fund this restock.
risk:    Stock covers about 0.5 weeks at 3.9 units/week;

in stock 2 · uncommitted 2 · sells 3.88/week · covers 0.52 weeks
stockout risk 0.7875 · margin per ₹ 0.35
priority = 0.7875 x 0.35 = 0.275617
supplier cost ₹74.00 · selling price ₹99.90
cost source: SEEDED_SUPPLIER_PRICE
```

**Say:** *"Every recommendation opens into the full calculation — stock,
velocity, lead time, margin, and the ranking arithmetic written out. The owner
can check the reasoning, disagree with it, and override it. It's not a black
box, and it's not a model's opinion."*

**Close on:** *"ShopFlow doesn't just tell a shop owner what's happening. It
helps them decide what to do next — and shows exactly why."*

## Recovery

| Symptom | Likely cause | Action |
|---|---|---|
| Planner already shows ₹6,300 / ₹12,948 at the start | Reset not run | Run Step 0, reload |
| Price list shows **no** material change | ₹6,300 already confirmed | Run Step 0, re-upload |
| Order spins then fails | Bedrock throttle or cold start | Retry once — it is usually transient |
| Order returns `NEEDS_CLARIFICATION` unexpectedly | Input text was edited | Re-paste the canonical order exactly |
| Any API call returns 429 | Stage throttle (20 rps / 40 burst) | Wait a few seconds; do not hammer |
| `/api/health` fails | Deeper problem | Check CloudFormation is `UPDATE_COMPLETE` and CloudWatch for errors |
| Page loads but calls fail | CloudFront/API routing | Confirm `/api/health` directly; check `/api/nope` still returns JSON 404 |
| Confirm button errors | Job expired (24h TTL) | Re-upload the price list to get a fresh job |
| Mic button disabled | Browser has no Web Speech API | Say so, and use the typed flow — the fallback is the point |
